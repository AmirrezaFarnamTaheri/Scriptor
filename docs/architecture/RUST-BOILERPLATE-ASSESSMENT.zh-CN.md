# Rust 样板代码评估

来源：用户在桌面上提供的 `Rust Boilerplate` 目录。该目录以只读方式检查。内容扫描覆盖 321 个文件（其中 314 个 Rust 文件；共 8,732,734 字节）；深入审查重点关注持久化、刷新、进程监管、Google 集成、Markdown 检查点和文件边界。

[逐文件清单](rust-boilerplate-inventory.json)记录了每个被扫描文件的相对路径、内容哈希、大小、类别和定向审查标记，使覆盖情况可供审计。完整的内容筛查并不表示每个代码片段都接受了正确性审查。分类仅辅助筛查，并非适用性或许可证判定。共有十四个源文件接受了定向审查。

该集合由多个系统的代码片段组成，并不是一个可构建的模板：它含有重复的编号模块名、对外部 crate 的引用、不相关的图形和压缩代码，而且没有统一的 Cargo 清单。可以将其中的模式适配到 Scriptor 现有的 crate；复制整个模块会引入未明示的依赖和假设。

## 已实现的适配

- 受保护的 frontmatter 写入会保留表格所加载的修订版本，拒绝多行单元格注入，并保留笔记正文。行为测试覆盖过期修订版本拒绝，以及使用新修订版本成功重试。
- 经审查的参考文献导入可以请求缺失的目标并绑定预期 Vault。无法读取的现有资源会被视为错误；绝不会静默替换。
- Android 调试打包支持可选的项目自有签名密钥、单 worker 内存限制、经过验证的原生库目标路径和进程环境还原。它不会修改全局调试密钥库。
- 阅读器批注队列将写入绑定到原始 Vault，并在回调变化时保留稳定队列。刷新失败会释放关闭门禁，让用户可以重试。批注存储会验证其父路径并拒绝非文件目标；不相关的检查失败不能触发损坏存储隔离。
- 首次协作共享使用以空内容表示的未知祖先。因此，首次传入共享可以应用到空的本地笔记，而不同的现有本地内容仍会在显式冲突中提供。经审查的合并在写入前会经过编辑器保存协调器和内容哈希比较。

这些都是 Scriptor 架构内的新实现。该集合中的源文件、凭据材料、遥测上传器、云作业启动器或不相关的压缩和图形实现均未被复制。进一步的同步和运行时适配仍需满足行为测试及现有能力契约。
