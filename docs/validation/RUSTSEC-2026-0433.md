# RUSTSEC-2026-0433 — nested image wikilink parser remediation

**2026-11-02** — GitHub Actions supply-chain gate [run 41436879805](https://github.com/AmirrezaFarnamTaheri/Scriptor/actions/runs/41436879805), diagram renderer PR #273, refused `pulldown-cmark` 0.13.5 (RUSTSEC-2026-0433). The upstream vulnerability allows quadratic parsing of deeply nested image-style wikilinks when `ENABLE_WIKILINKS` is enabled. The separate RUSTSEC-2026-0414 was already corrected by 0.13.5; this advisory requires the newer **0.13.6** release.

## Evidence and minimal change

- The [upstream fix](https://github.com/pulldown-cmark/pulldown-cmark/pull/1186) was released as 0.13.6 on 2026-10-30. The official [crates.io index file](https://github.com/rust-lang/crates.io-index/blob/master/pu/ll/pulldown-cmark) lists 0.13.6 as **not yanked**, with published checksum `3db2be46835f013dd3f4fa7f5f7402c537787b54ebb6fe2b94bbdd7e2669bb7b`.
- Compared the index records for 0.13.5 and 0.13.6: the complete normal/optional/dev dependency requirements, targets and feature keys are unchanged. A single `Cargo.lock` package version/checksum change is therefore sufficient for this compatible patch release.
- Raised the direct minimum versions in `crates/cli`, `crates/daemon`, `crates/extractor` and `crates/export-runner` to 0.13.6, preserving optional flags, feature selection and Markdown parser APIs. No `deny.toml` exception was added, and the 11 informational maintenance exceptions remain unchanged.
- The test-first commit adds a source regression which rejects a locked Markdown parser older than 0.13.6 and fails if someone ignores RUSTSEC-2026-0433. The original failed hosted audit demonstrates the pre-fix failure independently of the authored regression.
- Required acceptance: exact-head hosted `cargo deny` with a current RustSec database, locked Cargo build/unit/Clippy tests (including feature-gated PDF), source contracts, browser E2E, Windows and container smoke. No green claim before the hosted outcomes are observed.

## Limits

This compatible upstream patch removes the specific known parser defect; it does not prove that all untrusted Markdown inputs or all third-party dependencies are free of vulnerabilities. In-product native authorization, review, offline recovery and downstream receipt protections are unaffected. No real-device or independent human verification is a MAT completion prerequisite.
