## Сообщение об уязвимости

Не создавайте публичный issue, если подозреваете наличие уязвимости. Отправьте письмо на **taherifarnam@gmail.com** и укажите:

- затронутую версию или commit;
- окружение и предварительные условия;
- воспроизводимые шаги или proof of concept;
- влияние и пересечённые границы данных или полномочий;
- желаемый срок embargo или иные потребности в координации.

Не прикладывайте реальные секреты и персональные данные третьих лиц. Получение отчёта подтверждается настолько быстро, насколько это практически возможно; сроки раскрытия согласовываются после того, как станут понятны влияние и способ устранения.

## Поддерживаемая версия

Исправления безопасности выпускаются только для текущего tagged release и текущей ветки `main`. Идентичность релиза определяется файлом [`VERSION`](VERSION).

## Границы доверия

- **Renderer:** считается недоверенным относительно нативных полномочий доступа к файловой системе, keychain, процессам, резервным копиям, Git, сети и публикации.
- **Команды Tauri:** классифицируются по операциям; чувствительные команды требуют нового одноразового scoped grant, выдаваемого после нативного подтверждения пользователем.
- **Daemon/IPC:** локальный endpoint одного пользователя с защищёнными HMAC метаданными endpoint; для каждого запроса и подписки на события требуется nonce конкретного endpoint; сообщения типизированы и версионированы, размеры frames/queues ограничены, поддерживаются автоматическая аутентифицированная повторная подписка и явная ресинхронизация состояния после прерывания потока событий. В Windows безопасность локальных TCP/named-pipe endpoints основана на аутентификации bearer token HMAC-SHA256, который хранится в пользовательском `%LOCALAPPDATA%` или OS Credential Manager, а не на правах файловой системы Unix socket.
- **MCP:** явные инструменты, долговечные записи аудита intent/outcome, ключи идемпотентности, ограниченные журналы и восстановление незавершённых intents.
- **Внешние инструменты/code chunks:** запускаются через process broker с разрешением исполняемого файла, очисткой окружения, сетевой политикой, ограничениями времени/вывода, отменой дерева процессов и receipts.
- **Plugins:** текущий runtime ограничен и следует подходу manifest-first; согласие на разрешения, подписанная сторонняя дистрибуция и изолированное выполнение остаются требованиями для перехода функции в зрелое состояние.
- **AI providers:** учётные данные остаются внутри нативной границы keychain; сетевые вызовы выполняются Rust через проверенные endpoints и не раскрывают JavaScript необработанные секреты.

## Данные и конфиденциальность

Scriptor работает по принципу local-first и не требует телеметрии. Диагностика включается только по желанию пользователя и должна содержать лишь разрешённые и отредактированные поля. Remote PlantUML и удалённые шрифты отключены. Любая опциональная удалённая интеграция должна явно указывать endpoint и отправляемые данные.

## Состояние шифрования

`crates/vault/src/encryption.rs` содержит версионированные криптографические примитивы и тесты. **Зашифрованные vaults остаются экспериментальной возможностью и не являются поддерживаемой сквозной функцией безопасности.** Индексы, резервные копии, история Git, временные файлы, утечки метаданных, восстановление ключей и миграции не решаются одним лишь примитивом шифрования на уровне файла. См. [`docs/ENCRYPTION-THREAT-MODEL.ru.md`](docs/ENCRYPTION-THREAT-MODEL.ru.md).

## Целостность релиза

Официальные upstream-инсталляторы production-релизов намеренно публикуются без цифровой подписи. Их trust records прямо фиксируют отсутствие платформенной подписи и notarization. Вместо этого production-публикация требует для каждой целевой платформы явный trust-status record, SHA-256 checksums, CycloneDX SBOM, неизменяемый release receipt, точную идентичность исходного кода и GitHub provenance attestations. Инструкции по проверке: [`docs/RELEASE-SECURITY.ru.md`](docs/RELEASE-SECURITY.ru.md).
Последовательность production go/no-go описана в [`docs/RELEASE-CHECKLIST.ru.md`](docs/RELEASE-CHECKLIST.ru.md); текущая терминология доказательств и ещё не проверенные области перечислены в [`docs/VERIFICATION.ru.md`](docs/VERIFICATION.ru.md).

## Политика зависимостей и CI

- lockfiles являются входными данными валидации и не должны изменяться audit jobs;
- внешние GitHub Actions закрепляются за проверенными неизменяемыми commit SHA с точными комментариями версии;
- версии Node, pnpm, Rust, runners и release tools закреплены;
- CI запускает `cargo deny`, `pnpm audit --prod`, а также gates для action pins, версии, границ, документации и source contracts;
- обновления зависимостей выполняются отдельными проверяемыми изменениями.
