# In-process PDF export

The optional `inprocess-pdf` feature in `crates/export-runner/Cargo.toml` embeds the Typst compiler, PDF exporter and bundled fonts. It does not discover Pandoc, launch Typst, read installed fonts, download packages, or access network services. External Pandoc profiles remain a separate backend.

`compile_markdown_pdf(markdown, title, assets)` returns PDF bytes, the actual typeset page count, and bounded compiler warnings. Native adapters must run it on a blocking worker, authorize the originating vault, snapshot resources, and publish the resulting artifact through the existing vault write boundary. `markdown_image_paths` enumerates local image destinations before those reads. `PdfAsset.path` is the exact relative Markdown image destination; the compiler substitutes its own virtual resource identifier and never resolves a filesystem path.

The translator produces native headings, paragraphs, emphasis, ordered/unordered/task lists, quotations, fenced code, tables, safe HTTP/mail links and raster images. YAML frontmatter is omitted. Authored HTML and Typst syntax are literal text. Remote or unavailable images fail explicitly. This backend does not implement arbitrary Typst templates, CSL style selection, Mermaid/PlantUML execution, LaTeX math conversion or provider services; retain the external profile for those workflows.

Bounds are enforced before compilation: 256 KiB source, a 1024-byte title, 20,000 parser events, 64 nested containers, 4 MiB generated source, 32 image snapshots, 8 MiB per image and 32 MiB in total. Only PNG/JPEG snapshots with at most 16 megapixels are accepted. Output is limited to 256 pages and 32 MiB. Page/output limits apply after layout/serialization; they are not an OS memory quota or a preemptive deadline. Generated programs cannot contain authored loops, package imports or file reads. Compilation is serialized, and memoized document/resource values are evicted on both success and failure.

Fonts and data are embedded unmodified from the dependency. Redistribution notices are retained in `crates/export-runner/notices/typst-assets-NOTICE.txt` and exposed as `BUNDLED_ASSET_NOTICES`; packaged native license surfaces must display that text. No operating-system font availability is required. Bundled fonts do not guarantee complete coverage of every writing system; compiler warnings are returned to the caller.

Tests in `crates/export-runner/tests/inprocess_pdf.rs` exercise structured PDF output, accessibility structure, outlines, embedded fonts, repeatability, inert authored code, remote/missing/active-image rejection, input bounds and actual raster embedding. Module tests cover resource identifiers, oversized image dimensions, generated-code escaping and nesting bounds. The optional `SCRIPTOR_INPROCESS_PDF_ARTIFACT` test environment variable writes the successful structured fixture to an explicitly selected verification path for independent PDF inspection.

The feature-enabled export-runner run passed 69 tests across four suites; the existing external-Typst integration test remains intentionally ignored because it tests a different backend. Feature-specific Clippy and crate formatting passed. Independent inspection through the application's PDFJS reader decoded the structured fixture as one page, 24,504 bytes, with eight actual-text assertions, the expected heading outline and document title. The rendered page was visually inspected: headings, emphasis, bullets, quotation, table and monospace code are typeset rather than flattened into an image. The additional long-form fixture typesets onto multiple pages; unit coverage confirms YAML frontmatter and its image-like metadata are omitted.

The opt-in PDF fixture is `artifacts/verification/inprocess-typst.pdf`; its inspected rendering is `artifacts/verification/inprocess-typst.png`. `tests/inspect_pdf.mjs` performs the independent text/outline/title checks and optionally renders the first page for inspection. Artifact bytes are compared across repeated compilation in the Rust test. These generated artifacts are verification outputs, not release assets.

The cached Cargo advisory audit reported no known vulnerabilities and retained informational warnings for existing dependencies and the compiler's transitive, unmaintained `bincode` dependency through bundled syntax assets. That audit did not refresh the advisory database.

The mobile adapter enables this backend and exposes scoped `export_pdf` and `pdf_licenses` operations through its existing request boundary. The saved note hash must match the displayed source before snapshots are read and again after compilation. Image snapshots remain confined to the app-private vault. The renderer cannot submit an output destination. A native system save picker grants a path or provider URI for the immutable PDF; cancellation writes nothing. Official native dialog/filesystem plugins handle provider destinations, and iOS security-scoped access is released after the save attempt. A picker can suspend the app: selection authorizes the prepared snapshot, never a new vault root. Interrupted writes explicitly report that the selected destination may contain a partial file.

The phone UI exposes Save PDF, blocks export while a recovery draft is unsaved, reports cancellation and compiler warnings, and displays the complete bundled font notices in an accessible dialog. Three mobile boundary tests and four browser behavior tests passed, including saved-source hash binding, cancellation, notices, 320-pixel width and RTL/200-percent text controls. The mobile production TypeScript/Vite build and scoped ESLint passed; the lazily loaded editor retains the existing large-chunk advisory. Feature-enabled mobile-runtime tests passed eight tests across four suites. The native mobile Tauri library compiled on Windows and passed its two request-boundary/queue tests, including rejection of renderer-selected destinations and missing expected hashes. Mobile app/runtime all-targets Clippy passed with warnings denied, and formatting passed for the app/runtime/export crates. Browser tests mock the native boundary; native Android/iOS compilation, save-picker execution, provider permission behavior and physical-device performance remain platform verification gates.
