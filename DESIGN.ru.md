# Система дизайна

[English](DESIGN.md) · [فارسی](DESIGN.fa.md) · [简体中文](DESIGN.zh-CN.md) · **Русский** · [Deutsch](DESIGN.de.md) · [Español](DESIGN.es.md)

Scriptor — это интерфейс для **работы**: его открывают, чтобы писать, перемещаться по материалам, инспектировать, сравнивать и публиковать. Визуальная выразительность поддерживает эти задачи и никогда не конкурирует с ними.

## Направление

- Точный, спокойный, светлый и технический стиль без имитации IDE.
- Нейтральные угольно-/сланцевые поверхности с одним сдержанным семантическим акцентом.
- Плотная информация разделяется иерархией, ритмом и разделителями, а не вложенными карточками.
- Системный sans-serif для UI и системный monospace для кода и чисел; никаких удалённых шрифтов.

## Компоновка

На desktop используются четыре функциональные области:

1. верхняя панель команд;
2. rail vault/навигации;
3. рабочая область редактора/предпросмотра;
4. контекстный inspector и поверхности состояния.

На узких экранах вторичные области сворачиваются в мобильную навигацию workspace. Изменения workspace необходимо проверять при ширине `320`, `375`, `768`, `1024` и `1440` пикселей, а также при масштабе 200 %. Ни один элемент управления не должен зависеть только от hover.

## Anti-slop правила

- Никаких стандартных фиолетово-индиговых «AI-градиентов».
- Никакой чрезмерно крупной маркетинговой типографики на рабочих поверхностях.
- Никакого декоративного glassmorphism или фонового свечения; токенизированные стеклянные эффекты предназначены только для функционального chrome.
- Никаких emoji в роли структурных UI-иконок; используйте установленный набор Lucide.
- Никаких hover-scale трансформаций, сдвигающих layout.
- Никаких выдуманных оценок производительности, сертификатов завершения или заявлений о проверке без зафиксированных доказательств.

## Токены и настройка

Авторитетные токены находятся в `src/index.css` и `src/styles/`. Новые компоненты должны использовать семантические переменные для поверхностей, текста, границ, фокуса, опасности, предупреждения, успеха, отступов, радиусов и движения. Произвольные цвета и тени требуют документированного исключения.

| Роль токена | Runtime-переменная | Назначение / область |
|---|---|---|
| Основной акцент | `--primary` | Основные кнопки действий, индикаторы активной вкладки, ключевые badges |
| Вторичный янтарный | `--amber` | Предупреждения, badges промежуточного состояния, вторичные акценты |
| Основной фон | `--bg` | Корневой фон canvas приложения |
| Вторичная поверхность | `--surface` | Панели, боковые панели, карточки modal dialogs |
| Приподнятая поверхность | `--surface-raised` | Hover-состояния, приподнятые карточки, dropdown-элементы |
| Основной текст | `--ink` / `--ink-strong` | Высококонтрастный основной текст и заголовки |
| Подсветка границы | `--border` | Тонкие границы панелей и стеклянных краёв |
| Кольцо фокуса | `--focus-ring` | Контур клавиатурного фокуса |
| Шрифт интерфейса | `--font-sans` | Выбор семейства UI-шрифта (`system`, `inter`, `sf-pro`, `avenir-next`, `outfit`, `jetbrains-mono`, `georgia`) |
| Размытие стекла | `--glass-blur` | Интенсивность backdrop filter (`none`, `subtle`, `glass`, `heavy`) |

### Каталог цветовых схем и Custom Theme Builder

Scriptor поставляется с **18 встроенными тщательно настроенными цветовыми схемами** в трёх категориях (`dark`, `light`, `contrast`):
- **Тёмные:** `Dark Midnight`, `Catppuccin Mocha`, `Dracula`, `Nord Frost`, `Tokyo Night`, `Solarized Dark`, `Gruvbox Dark`, `Emerald Forest`, `Cyberpunk Neon`, `Monokai Pro`, `Rosé Pine`, `Synthwave 84`, `One Dark Pro`, `Vitesse Dark`.
- **Светлые:** `Light Modern`, `Sepia Paper`.
- **Высокий контраст:** `High Contrast`, `OLED True Black`.

Пользователи также могут открыть **Custom Theme Builder**, чтобы создавать, редактировать, просматривать в реальном времени и удалять пользовательские темы, динамически хранящиеся в `scriptor:custom-themes`.

## Контракт взаимодействия

Каждая асинхронная поверхность должна показывать только те состояния, которые её владелец способен определить. Где поддерживается, необходимо предоставить:

- загрузку или прогресс;
- полезное пустое состояние;
- ошибку с понятным действием;
- видимое подтверждение изменения;
- отмену длительной операции.

Операции высокого риска показывают область действия и последствия в нативном запросе подтверждения. Отключённые элементы управления объясняют причину. Разрушающие действия не являются действиями по умолчанию.

## Минимум по доступности

Цель: WCAG 2.2 AA.

- семантический HTML раньше ARIA;
- видимый `:focus-visible` для каждого интерактивного элемента;
- логичный порядок Tab и отсутствие клавиатурных ловушек;
- modal dialogs используют labels/descriptions, начальный и удерживаемый фокус, обработку Escape, блокировку прокрутки и восстановление фокуса;
- вкладки поддерживают стрелки, Home, End и roving `tabIndex`;
- состояние не передаётся одним только цветом;
- движение учитывает `prefers-reduced-motion`;
- touch-ориентированные элементы управления имеют размер не менее 44×44 CSS-пикселей;
- текст редактора и UI остаётся читаемым при 200 % масштабе;
- токены третичного текста сохраняют контраст WCAG AA на основных поверхностях;
- редактор следует светлой/тёмной теме приложения, пока пользователь явно не переопределит её.

## Движение

Анимация используется только для передачи изменений состояния. Стандартные переходы длятся 120–220 мс и используют opacity или transforms, не меняющие семантику содержащего блока. Нельзя непрерывно анимировать критичные для layout ширину или высоту. Режим reduced motion отключает необязательные переходы и smooth scrolling.

## Архитектура компонентов

- данные и оркестрация находятся в hooks или domain controllers;
- презентационные компоненты получают типизированные props;
- общие overlays используют единую примитиву dialog/panel;
- компоненты длиннее 200 строк считаются кандидатами на декомпозицию;
- packages предоставляют поведение только через объявленные entry points;
- состояния загрузки, пустоты, ошибки и успеха остаются у владельца, который способен достоверно их определить.

## Результаты Slop-Audit

По состоянию на 2026-08-09:
- **Сырые emoji:** 0 экземпляров в production TSX-файлах (100 % Lucide SVG icons).
- **Неконтролируемый `transition: all`:** 0 экземпляров среди 433 CSS- и TSX-файлов.
- **Явные `any` casts в UI:** 0 экземпляров в production TSX-компонентах.
- **Проверка контрактов:** 43 набора unit-тестов и validation успешно проходят на 100 % в `pnpm check:source`.

## Визуальная проверка

Проекты Playwright покрывают светлую/тёмную темы, desktop/mobile breakpoints, modal surfaces, editor/preview, knowledge workbench, settings, graph и основные состояния workflows. Зафиксированный release candidate дополнительно требует ручной проверки при масштабе 200 %, со screen reader и в native shell, пока эти проверки не будут надёжно автоматизированы. Пороговые значения snapshot не должны скрывать сдвиг всей страницы. См. [`docs/validation/FRONTEND_QUALITY.ru.md`](docs/validation/FRONTEND_QUALITY.ru.md).
