# Research workspace verification

Database Studio, Capture Reviewer, and the Reference desk are experimental desktop workflows. The renderer composes existing vault operations and the explicitly authorized research preview bridge. Markdown and bibliography files remain authoritative in the vault.

## Workflows and limits

- **Database Studio:** open it from the command palette or the saved-views workbench. Build title, tag, path, modified-day, and scalar YAML equality filters. YAML equality applies to at most the first 200 query candidates and the 32 MiB content budget; status text states this scope. Table, list, and gallery layouts share the loaded values. Declarative calculations reject executable operators and invalid calendar dates. Aggregates cover loaded rows. Editing scalar fields uses the source-note mutation coordinator and a fresh native content hash; formulas remain read-only.
- **Saved database views:** definitions live in `.scriptor/presets/database-studio.md`. Initial creation requires a missing destination; later saves require the loaded hash and vault identity. Failed reads and malformed definitions disable saving and offer a reload action. Browser-only definitions are vault-keyed local storage and cannot query or modify vault notes.
- **Capture Reviewer:** an explicit Extract preview action requests native `web_clip` authorization. The user can review extracted text beside the editable Markdown, add highlights, edit source metadata, and choose a relative vault directory. A passive original-source snapshot retains text and structure from the same bounded fetch in a sandboxed frame. Scripts, resources, styles, forms, links and navigation are removed; an independent restrictive frame policy blocks network access. This snapshot does not reproduce original page pixels. Saving requires a new destination and the expected vault identity. The external source link opens only when selected.
- **Reference desk:** bibliography entries expose authors, years, source paths, abstracts, DOI, URLs, and attachments. References can insert or drag citation text into the editor and create literature notes containing citation/source metadata and abstracts. A user-triggered citation scan lists missing references and references unused in scanned notes. Truncated scans explicitly identify possibly unused results as incomplete.
- **Bibliography imports:** local `.bib` files have an 8 MiB preview limit. Zotero pages require separate user-triggered native `zotero_read` grants; preview holds at most 1000 unique references. The user reviews entries and BibTeX, selects references, and saves a new `.bib` path. Imports never overwrite an existing bibliography. Zotero keys stay in transient component state and are cleared on cancellation/success; neither the fixture nor the import files contain them. Users should select the new bibliography path in export settings when they want Pandoc to use that file.

All asynchronous operations use generation checks and synchronous operation latches. Closing a panel abandons renderer updates; an already submitted native write may finish. Scope and stale-content checks remain native responsibilities.

## Evidence

- [Database behavioral tests](../../src/lib/databaseStudio.test.ts): scalar projection/filtering, bounds, path escaping, declarative formulas, aggregates, calendar validity, and exact missing-preset classification.
- [Reference behavioral tests](../../src/lib/referenceDesk.test.ts): bounded/deduplicated Zotero metadata, BibTeX escaping, citation usage runtime validation, and literature-note source metadata.
- [Capture behavioral tests](../../src/lib/captureReviewer.test.ts): relative destination confinement and quoted metadata/source attribution.
- [Research browser tests](../../e2e/research-workspaces.spec.ts): actual panel orchestration against the opt-in [native-command fixture](../../src/e2e/research.harness.ts). Coverage includes saved view persistence, malformed-preset protection, inline YAML editing, layout/formula/aggregate presentation, extraction failure, reviewed highlight/content saving, Zotero pages and reviewed writes, `.bib` overwrite refusal, literature note creation, and responsive/zoom reachability.

The focused logic suites pass with 11 tests. The expanded research browser suite passes eight tests (final run: 38.4 seconds). All three panels were checked at 320, 375, 768, 1024, and 1440 CSS pixels and at 200% zoom. Six screenshots at 320 and 1440 pixels were captured under `artifacts/research-browser` and visually inspected. The tests exposed and verify fixes for inherited bibliography grid rows overlapping the Zotero paging control and viewport-unit sizing moving a close action outside the viewport at 200% zoom. Visual inspection also identified and fixed translucent Database/Capture dialogs; opacity is covered by the browser assertions. TypeScript project compilation and focused ESLint checks pass.

This browser evidence uses deterministic native-command mocks. It does not prove live Zotero credentials/network access, native web extraction, packaged application behavior, or a manual screen-reader audit. Native compilation and command tests are recorded by their owning verification gate.
