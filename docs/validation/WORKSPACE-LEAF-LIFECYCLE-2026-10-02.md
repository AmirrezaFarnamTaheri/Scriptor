# Workspace leaf lifecycle guards

Workspace composition keeps opened leaves mounted when switching tabs. Closing one leaf uses a scoped controller rather than broadcasting the global vault-change event. The root activates that leaf and keeps it visible/mounted while its guard resolves. Each owner registers an asynchronous guard under the provider's leaf ID; concurrent close requests share one decision. Rejection, false, or changed guard ownership cancels close. Multiple owners participate sequentially.

Source editors register their own save/discard/keep decision. Busy compilation, file operations and sync decline close until the operation finishes. Failed saving returns false and preserves the draft/error. Hidden dirty editors reveal their own leaf when the global vault-change listener asks for a decision. An internal editor close consumes a one-use owner approval when root checks its leaf, preventing a second discard prompt.

Persistent Python owners register their existing stop workflow. Confirmed shutdown approves close; shutdown failure declines close and reveals the originating leaf for retry. The fresh-process panel separately declines close while its bounded execution is active, preserving its existing broker completion behavior. Native process authority, source CAS, one-use execution consent, vault transition locking and broker cleanup remain enforced by their existing native commands. The frontend controller grants no native authority and cannot bypass those checks. Vault transitions continue to notify all mounted owners separately.

Vault-switch listeners may enqueue deferred asynchronous guard factories. The dispatcher invokes these sequentially, so multiple hidden dirty source leaves reveal one decision at a time. Refusal or failure stops the sequence before revealing later leaves. Existing eager promise listeners remain compatible and their rejection handlers attach immediately, including when an earlier deferred decision refuses.

Three controller behavioral tests verify leaf isolation/retry, shared pending decisions and fail-closed ownership/failure handling. Three vault-switch tests verify existing promise compatibility, sequential prompt activation, refusal/failure short-circuiting and eager rejection observation. Failing behavioral coverage preceded both implementations. TypeScript and focused lint pass. Integrated browser coverage is coordinated by the root after shell integration; no new browser evidence is claimed here yet.
