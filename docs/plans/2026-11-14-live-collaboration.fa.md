# اسکریپتور: برنامهٔ پیاده‌سازی ویرایش هم‌زمان

> برای عامل‌های مهندسی: هر بخش باید مستقل آزموده شود و شواهد شکست اولیه و موفقیت نهایی ثبت شود.

**هدف:** ویرایش هم‌زمان چند کاربر در کلاینت‌های Scriptor، همراه با بازیابی آفلاین؛ بدون معرفی نظرسنجی Google Docs یا همگام‌سازی Git در Overleaf به‌عنوان ویرایش زندهٔ بومی.

**معماری:** پروتکل نسخه‌دار هر به‌روزرسانی را به شناسهٔ مخزن، اتاق، سند، دوره و همتا گره می‌زند. CRDT متنی سازگار با Yjs تغییرات هم‌زمان را به همگرایی می‌رساند. لایهٔ بومی دفتر ثبت پایدار و مرز نوشتن فایل را مدیریت می‌کند؛ رلهٔ احراز‌هویت‌شدهٔ WSS فقط پس از ثبت پایدار پاسخ ACK می‌دهد. CodeMirror و Monaco تراکنش‌های افزایشی می‌فرستند و سرویس‌های بیرونی تنها از آداپتورهای جداگانه و بازبینی‌شده استفاده می‌کنند.

**فناوری:** TypeScript و Node 22، ‏React، ‏CodeMirror 6، ‏Monaco، ‏Rust/Tauri، ‏SQLite WAL، ‏Yjs و WebSocket احراز‌هویت‌شده.

## محدودیت‌های سراسری و امنیت

- شناسه‌های مخزن، اتاق، سند، دوره و همتا باید دقیقاً مطابقت داشته باشند؛ رضایت کاربر برای هر سند جداگانه اخذ شود.
- سقف‌ها: ۲۵۶ کیبی‌بایت برای به‌روزرسانی، ۲ کیبی‌بایت برای وضعیت حضور، ۲ میبی‌بایت برای متن نهایی سند و ۶۴ میبی‌بایت برای صف محلی تأییدنشده.
- کاربر محروم‌شده حق خواندن یا نوشتن ندارد؛ بیننده حق نوشتن ندارد. پاسخ قدیمی نباید سند نشست فعلی را تغییر دهد.
- ACK باید نتیجهٔ یک تراکنش پایدار رله باشد، نه صرفاً ارسال پیام. تغییرات پذیرفته‌شدهٔ محلی باید پس از راه‌اندازی مجدد حفظ شوند.
- انتقال بازنگری‌های تغییرناپذیر Drive/Docs، نظرسنجی محدود، Git فعلی Overleaf و سازوکارهای CAS و بازیابی همچنان مستقل کار کنند.
- از واسط‌های خصوصی و مستندنشدهٔ ویرایشگر Overleaf استفاده نشود؛ پیش از آزمون واقعی، هم‌زمانی بومی سرویس‌های بیرونی ادعا نشود.
- شاخهٔ مستقل مبتنی بر main استفاده شود؛ تغییرات با PR #336 ادغام نشوند؛ درخواست ادغام تا پایان آزمون‌ها پیش‌نویس بماند.

## مراحل مستقل بعدی

**M2 Overleaf:** کل پروژه با Git رسمی و مسیرهای ایمن؛ بازبینی فایل‌های دودویی، حذف و تعارض؛ بدون force push.

**M3 Google Docs:** مدل ساختاری برای برگه‌ها، سبک‌ها، فهرست‌ها، پیوندها و جدول‌ها؛ درخواست‌های انتخابی batchUpdate با کنترل بازنگری؛ بدون حذف خاموش دادهٔ پشتیبانی‌نشده.

**M4 سازگارسازی سرویس‌ها:** نقطه‌های کنترل سرویس مستقل از ACK مربوط به CRDT باشند؛ اختلاف بیرونی دوباره بررسی شود.

**M5 ویرایشگر بومی Overleaf:** تنها بعد از عرضه و بررسی پروتکل رسمی پشتیبانی‌شده.

**تصمیم تأیید‌شده:** استقرار اول خودمیزبان و بدون رمزگذاری سرتاسری است؛ امکان دسترسی گردانندهٔ رله باید شفاف توضیح داده شود. میزبانی مدیریت‌شده، نوشتن خودکار در سرویس و رابط غیررسمی، تأیید جداگانه می‌خواهد.
