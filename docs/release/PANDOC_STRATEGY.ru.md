# Стратегия Pandoc

[English](PANDOC_STRATEGY.md) · [简体中文](PANDOC_STRATEGY.zh-CN.md) · **Русский** · [Deutsch](PANDOC_STRATEGY.de.md) · [Español](PANDOC_STRATEGY.es.md) · [فارسی](PANDOC_STRATEGY.fa.md)

Scriptor выполняет экспорт через Pandoc с явным списком разрешённых аргументов. Десктопное приложение и CLI используют общую логику обнаружения из `scriptor-export-runner`.

## Порядок разрешения

1. **`SCRIPTOR_PANDOC_PATH`** — абсолютный путь к исполняемому файлу Pandoc. Используется, если IT устанавливает Pandoc вне `PATH` или если присутствуют несколько версий.
2. **`pandoc` в `PATH`** — вариант по умолчанию. В Windows путь определяется через `where pandoc`, в Unix — через `which pandoc`.

Проверка обнаружения:

```powershell
pnpm cli -- export-discover
```

## Варианты установки

| Подход | Статус | Примечания |
|---|---|---|
| Системный Pandoc в `PATH` | **По умолчанию** | Соответствует типичным конфигурациям опытных пользователей; минимальный установщик. |
| Переопределение `SCRIPTOR_PANDOC_PATH` | **Поддерживается** | Предназначено в том числе для корпоративных развёртываний. |
| Pandoc внутри установщика | **Опционально** | `SCRIPTOR_BUNDLED_PANDOC_DIR` + `scripts/release/install-bundled-pandoc.ps1` |

Dry-run экспорта работает и без установленного Pandoc — он только показывает аргументы. Для реального экспорта нужен рабочий бинарник Pandoc и движки конкретного формата, например LaTeX для PDF.

## Рекомендуемая установка

**Windows (winget):**

```powershell
winget install --id JohnMacFarlane.Pandoc
```

**macOS (Homebrew):**

```bash
brew install pandoc
```

**Linux:** пакет дистрибутива или официальный архив релиза Pandoc.

## Типичные сбои

| Симптом | Исправление |
|---|---|
| `pandoc was not found on PATH` | Установить Pandoc или задать `SCRIPTOR_PANDOC_PATH`. |
| Dry-run проходит, реальный экспорт падает | Не хватает filter/engine Pandoc для выбранного формата. |
| Выбирается неверная версия Pandoc | Указать нужный бинарник через `SCRIPTOR_PANDOC_PATH`. |

## Лицензионная граница Pandoc GPL / AGPL

Pandoc распространяется по **GPL-2.0-or-later**. Scriptor — по **AGPL-3.0-or-later**. Лицензии совместимы для распространения, однако способ вызова Pandoc остаётся важной границей.

### Как Scriptor использует Pandoc

Scriptor запускает Pandoc как **внешний процесс** через `std::process::Command` в `crates/export-runner`. Исходный код Pandoc не линкуется со Scriptor ни статически, ни динамически. GPL-код Pandoc не входит в адресное пространство Scriptor.

```
┌──────────────┐   subprocess   ┌──────────────┐
│ Scriptor      │ ─────────────→ │ pandoc        │
│ (AGPL-3.0)   │ ←───────────── │ (GPL-2.0+)   │
└──────────────┘   stdout/file  └──────────────┘
```

### Практические последствия

| Сценарий | Лицензионная обязанность |
|---|---|
| Scriptor поставляется без Pandoc | Обязанностей по GPL для Pandoc нет; пользователь устанавливает его отдельно. |
| Scriptor включает Pandoc в установщик | Pandoc остаётся отдельным произведением; установщик должен соблюдать GPL-2.0+ для бинарника Pandoc (предложение исходников, уведомление о лицензии). AGPL-3.0+ Scriptor относится только к коду Scriptor. |
| Scriptor вызывает Pandoc во время работы | Обязанность «combined work» не возникает; вызов отдельного процесса не является линковкой. |
| Scriptor распространяет фильтры Pandoc | Фильтры, импортирующие модули Pandoc, являются производными произведениями GPL-2.0+. Фильтры Scriptor, общающиеся только через stdin/stdout, остаются отдельными произведениями. |

### Allowlist для `extra_pandoc_args`

Пользовательские `extra_pandoc_args` проходят allowlist в `crates/export-runner/src/allowlist.rs`. Это предотвращает произвольную инъекцию аргументов и пропускает в подпроцесс Pandoc только задокументированные безопасные флаги. Allowlist — граница безопасности, а не лицензионный механизм.

### Встроенный Pandoc (опционально)

Если Scriptor когда-либо начнёт включать Pandoc в установщик (`SCRIPTOR_BUNDLED_PANDOC_DIR`), release-процесс обязан:

1. поставлять файл лицензии Pandoc рядом с бинарником;
2. включать письменное предложение исходного кода Pandoc согласно GPL-2.0 §6;
3. документировать версию и лицензию Pandoc в release notes.

Эти обязанности относятся только к бинарнику Pandoc, а не к Scriptor.

## Безопасность

- Аргументы экспорта строятся из типизированных структур Rust, а не конкатенацией shell-строк.
- `extra_pandoc_args` проходят allowlist в `export-runner`.
- Если встроенный Pandoc будет добавлен, `export-discover` должен сообщать закреплённую версию для диагностики поддержки.
