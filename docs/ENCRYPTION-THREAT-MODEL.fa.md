# مدل تهدید مخزن رمزگذاری‌شده

**تصمیم:** رمزگذاری همچنان آزمایشی است. وجود primitiveهای رمزنگاری به‌معنای داشتن یک محصول مخزن رمزگذاری‌شده سرتاسری نیست.

## دارایی‌ها

محتوای Markdown، پیوست‌ها، پیکربندی، ایندکس‌ها، عبارت‌های جست‌وجو، فراداده گراف/پیوند، تاریخچه Git، نسخه‌های پشتیبان، خروجی‌های موقت، لاگ‌ها، آرگومان‌های فرایند، کلیدها و داده‌های بازیابی.

## تهدیدهای داخل دامنه

- دستگاه خاموشِ گم‌شده یا دزدیده‌شده؛
- کپی آفلاین از یک vault یا backup؛
- باقی‌ماندن ناخواسته متن ساده هنگام migration/export/restore؛
- عبارت عبور ضعیف و downgrade پارامترها؛
- از دست رفتن کلید و rekey/migration ناتمام؛
- نشت فراداده از مسیرها، ایندکس‌ها، Git، لاگ‌ها، thumbnailها، swap یا crash dumpها.

## تهدیدهایی که رمزگذاری فایل‌به‌فایل حل نمی‌کند

سیستم‌عامل یا نشست کاربری در حال اجرا که compromise شده باشد، renderer مخربی که از قبل اختیار دریافت کرده، keylogger، ابزار خارجی مخرب، متن ساده‌ای که در حافظه نمایش داده می‌شود، یا مهاجمی که به keychain یا داده‌های نشستِ بازشده دسترسی دارد.

## معماری لازم پیش از ارتقا

1. envelope نسخه‌بندی‌شده شامل شناسه‌ها و پارامترهای الگوریتم/KDF؛
2. طراحی بازیابی با OS keychain و عبارت عبور، همراه با semantics صریح برای از دست رفتن دسترسی؛
3. راهبرد ایندکس/گراف/cache که یا رمزگذاری شده باشد یا آگاهانه از دامنه خارج شده باشد؛
4. journal اتمیک برای migration/rekey همراه با rollback؛
5. backup خارجی رمزگذاری‌شده و تمرین restore؛
6. سیاست Git برای جلوگیری از ثبت تاریخچه plaintext؛
7. مدیریت امن فایل‌های موقت/export؛
8. بازبینی مستقل رمزنگاری، known-answer test، fuzzing، fault injection و آزمون migration پارامترها؛
9. UI که وضعیت locked/unlocked و میزان نشت فراداده را دقیق بیان کند.

## پیاده‌سازی فعلی

`crates/vault/src/encryption.rs` از authenticated encryption و مشتق‌سازی عبارت عبور مبتنی بر Argon2id با بررسی نسخه و آزمون‌های منفی استفاده می‌کند. این یک ماژول کتابخانه‌ای نمونه است و به‌عنوان حالت شفاف و پشتیبانی‌شده vault متصل نشده است. مستندات محصول و امنیت باید این تمایز را حفظ کنند.
