# Visual reinspection after the detached Asset Deck checkbox

The prior visual audit checked overflow and the clickable label's height, but did not check the checkbox's position relative to its text. Those checks passed a detached control. Its previous passing result is not evidence that all visual details were correct.

The expanded inspection found analogous detached controls in Diagram Studio and Runtime Console, an unnecessarily tall runtime environment field, missing Publishing Studio form styling on a fresh opening, RTL inheritance in technical source and identifier fields, a cramped Capture URL row, and duplicate plugin workspace landmarks. The reported Runtime workspace overview heading also inherited a broad legacy header selector: narrowing the container squeezed the title beside its description. The legacy selector now targets only its owning header, and the plugin header stacks according to available container width.

New browser coverage checks label/control alignment and proximity, text-click and keyboard activation, light/dark appearance, LTR/RTL, narrow and desktop widths, 200% zoom, and fresh panel openings. Screenshots require direct inspection in addition to geometry assertions. The stricter 320-pixel zoom checks also exposed overflow that the earlier matrix did not cover.

Additional reinspection exposed invalid outline colors using a shadow-valued token, unthemed Diagram controls and source text areas, undersized populated Capture fields, and a burst-zoom race that left responsive state behind the actual zoom factor. High zoom also allowed repeated headers and navigation to consume the panel body. The repaired shell compacts chrome, retains named navigation, moves tab actions to an opaque bounded disclosure, preserves keyboard focus, and wraps the footer at the narrowest effective width. Embedded panels use one owning Close control, pure title headers collapse at high zoom, and nested dialogs retain their controls. The oversized Writing pill and nested Asset Deck padding are removed at the appropriate scope. A range-based check verifies that “Unused” does not split mid-word at maximum zoom.

Coverage is split across `control-label-cohesion.spec.ts`, `review-panel-appearance.spec.ts`, `review-focus-indicators.spec.ts`, `populated-review-visual.spec.ts`, `zoomed-workspace-chrome.spec.ts`, `plugin-workspaces.spec.ts`, and the expanded `new-feature-visual-audit.spec.ts`. These 42 passing cases check actual control/text proximity and activation, fresh opening styles, named focus outlines, populated forms, rendered diagram SVGs, viewport bounds, single owning Close controls, and usable panel content. Actual shortcut-driven CSS fallback zoom is exercised at approximately 2.15x and the supported 2.5x maximum on 320/375-pixel windows in LTR/RTL. Eight zoom cases verify bounded controls, intact “Unused” text, keyboard disclosure dismissal and at least 250 displayed pixels of panel body. Fresh-panel captures include the entire workspace as well as panel top/bottom views.

The broader integration run plus targeted rechecks verify 81 distinct scenarios, including 39 workflow regressions. Source/contract validation, 497 source tests, TypeScript, lint, production build, dependency audit and whitespace checks pass. The detailed run accounting is in `WORKSPACE-COMPOSITION-2026-10-02.md`.

This evidence is from the installed Edge browser with native fixtures. It does not assert product-wide visual perfection, packaged WebView/native zoom equivalence, live provider verification or physical mobile verification. Geometry alone is insufficient: screenshots are reviewed directly as part of this pass.

Full-page populated screenshots also exposed browser-default workspace launcher buttons in dark appearance. Launchers now use explicit theme surfaces, text, borders and focus outlines. Fresh-panel coverage measures their text contrast (at least 4.5:1) and checks their styled shape in both appearances rather than assuming a loaded stylesheet themed them.

Fresh full-page captures exposed stretching of Capture's empty grid rows. Its content now starts at the top, with a regression bounding the gap between heading and URL form. Appearance tests switch themes through the application control, allowing editor theme state to update as well as CSS; direct attribute changes are no longer used for those captures. Top captures reset the panel scroll position before saving the full workspace image.
