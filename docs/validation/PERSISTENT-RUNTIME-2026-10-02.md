# Persistent runtime review and implementation

Original Gemini review lines 405–410 proposed a runtime console retaining variables, reviewed environments, interactive stdout and plots. The prior console launched a fresh process for each run. The complete Visual Review/scratchpad reread and reconstructed lineage are recorded in VISUAL-SCRATCHPAD-REVIEW-2026-10-02.md; this report adds current implementation evidence.

Persistent Python now uses one vault-owned UUID session and the existing process broker. Each start binds consent to the reviewed environment; each run binds consent to the exact source and session. The private mailbox carries bounded JSON, live stdout/stderr, primitive variable previews and at most three bounded PNGs. Matplotlib is optional and uses Agg; scriptor_display_png accepts explicit PNG bytes. Other languages retain the existing fresh-process behavior. Interactive stdin, installing environments/packages and persistence across application restarts are outside this bounded workflow.

Sessions expire after 15 minutes; cells have a 30-second deadline. Stop/restart cancel the broker process tree and clear private artifacts. Shutdown failures remain visible and block switching; retained ownership permits a retry. A native transition guard serializes final startup validation/registration with vault transitions. Armed startup cancellation and capacity guards survive the blocking-task result until registry adoption, including an abandoned caller. Late frontend startup results are stopped; failed cleanup retains their identity.

Native behavioral coverage executes Python through the actual broker: namespace retention, exceptions, truncated output and PNG delivery; stop during an infinite cell; pending registration after a vault change; abandoned startup-result cleanup. Browser coverage uses an explicit native fixture to verify permission scopes, persistence/restart, PNG rendering, mobile live-output cancellation, vault shutdown and failed deferred-start cancellation/retry. Browser fixtures do not claim a real native process ran.

Scoped boilerplate inspection: the complete 195-line Desktop Rust Boilerplate terminal.rs uses owned terminal sessions and explicit kill/resize. Ownership and cancellation informed this implementation; direct PTY spawning and unbounded output were not copied because Scriptor requires its process broker. Inventory of the ten python*.rs files found mostly AST extractors and LSP/debugger/toolchain adapters, rather than a reusable persistent kernel. This scoped pass does not claim a fresh full reread of every large Python adapter; the earlier full boilerplate investigation remains recorded separately.

Verification: four runtime browser workflows passed on the production E2E bundle (24.8 seconds); TypeScript and focused ESLint passed. Five native behavioral tests are present, including real process cancellation and abandoned startup cleanup; the parent agent runs their coordinated native/Clippy gates and records final counts.
