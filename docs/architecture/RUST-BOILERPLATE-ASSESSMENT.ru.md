# Оценка Rust boilerplate

Источник: предоставленный пользователем каталог `Rust Boilerplate` на рабочем столе. Каталог был проверен только для чтения. Контент-сканирование охватило 321 файл (314 файлов Rust; 8 732 734 байта); углублённая проверка сосредоточилась на персистентности, обновлении, надзоре за процессами, интеграции с Google, контрольных точках Markdown и файловых границах.

[Пофайловый инвентарь](rust-boilerplate-inventory.json) содержит каждый просканированный относительный путь, хеш содержимого, размер, категорию и маркер целевой проверки. Это делает покрытие проверяемым; полный просмотр содержимого не означает, что каждый фрагмент прошёл проверку корректности. Категории служат для первичного отбора, а не для определения пригодности или лицензии. Целевую проверку прошли четырнадцать исходных файлов.

Коллекция состоит из фрагментов нескольких систем, а не представляет собой собираемый шаблон: в ней есть повторяющиеся нумерованные имена модулей, ссылки на внешние crates, несвязанный код графики и сжатия, и отсутствует общий Cargo manifest. Паттерны можно адаптировать к существующим crates Scriptor; копирование целых модулей привнесло бы неоговорённые зависимости и предположения.

## Реализованные адаптации

- Защищённая запись frontmatter сохраняет загруженную таблицей ревизию, отклоняет внедрение многострочного значения ячейки и сохраняет тело заметки. Поведенческие тесты покрывают отклонение устаревшей ревизии и успешную повторную попытку со свежей ревизией.
- Проверенный импорт библиографии может запросить отсутствующее назначение и привязать ожидаемое хранилище. Нечитаемый существующий ресурс считается ошибкой и никогда не заменяется молча.
- Android debug-упаковка поддерживает необязательный принадлежащий проекту ключ подписи, однопоточные ограничения памяти, проверяемое место назначения нативной библиотеки и восстановление окружения процесса. Она не изменяет глобальный debug keystore.
- Очереди аннотаций Reader привязывают записи к исходному хранилищу и сохраняют стабильную очередь при изменении callback-функций. Неудачный flush освобождает блокировку закрытия, чтобы пользователь мог повторить попытку. Хранилище аннотаций проверяет родительский путь и отклоняет назначения, не являющиеся файлами; несвязанные ошибки проверки не могут запустить карантин повреждённого хранилища.
- Первые публикации для совместной работы используют неизвестного предка, представленного пустым содержимым. Поэтому первый входящий share может примениться к пустой локальной заметке, а отличающееся существующее локальное содержимое остаётся доступным в явном конфликте. Проверенные слияния перед записью проходят через координатор сохранения редактора и сравнение хешей содержимого.

Это новые реализации в архитектуре Scriptor. Из коллекции не копировались исходные файлы, данные учётных записей, отправщики телеметрии, cloud job launcher или несвязанные реализации сжатия и графики. Дальнейшие адаптации sync/runtime остаются обусловлены поведенческими тестами и существующими контрактами возможностей.

## Полное повторное исследование 2026-10-01

[Второй инвентарь](rust-boilerplate-reinvestigation.json) содержит результаты нового полного просмотра содержимого всех 321 файлов с корнями импортов, количеством функций, тестами и сигналами границ. Тесты присутствуют в 134 файлах, маркеры `unsafe` — в 20, а маркеры лицензии — в восьми; это наблюдения первичного отбора, а не заключение об уязвимостях или лицензиях. Первоначальная целевая проверка четырнадцати файлов дополнена следующими проверками на уровне методов.

| Дополнительный источник | Оценка | Решение |
|---|---|---|
| `auth_backend_contract_tests.rs` | Отличает явные верхнеуровневые постоянные коды OAuth от повреждённых, вложенных, throttled- и серверных ошибок; тесты конкурентного обновления повторно проверяют состояние внутри блокировки | Классификация ответов адаптирована к нативному обновлению Google с падающим регрессионным тестом до исправления; добавлены ограниченное чтение токена и проверяемая арифметика срока действия. Существующая блокировка обновления сохранена. |
| `auth_provider.rs`, `auth_provider_tests.rs` | Явный запуск программы и аргументов, предельные тайм-ауты, ограниченный вывод и ключи кэша, включающие конфигурацию провайдера | Полезные идеи для тестирования жизненного цикла runtime. Его shell fallback и внедрение first-party учётных данных через окружение не приняты; все процессы Scriptor остаются брокерованными. |
| Методы snapshot в `compute.rs` | Неизменяемые snapshots с проверкой хеша, потоковое хеширование, приватное хранилище и конкурентные проверки назначения | Применить принцип неизменяемого snapshot при устранении гонок staging для развёртывания. Не копировать его cloud launcher, shell-скрипт snapshot или удаление существующих недействительных назначений. |
| Методы диапазонов и ответов в `file_serve.rs` | Обрабатывает suffix ranges, пустые и недопустимые диапазоны, ограниченные длины, `nosniff` и sandboxing активных форматов документов | Полезные контракты для более широких предпросмотров медиа. Сейчас Scriptor обслуживает включённые в пакет ресурсы reader, поэтому эквивалентность диапазонов байтов не заявляется. |
| Методы потокового состояния `open_code_highlighter.rs` | Мемоизирует стабильные завершённые строки и клонирует предварительное состояние хвоста; явно документирует квадратичное перестроение вывода | Граница стабильного и предварительного состояния полезна; не заявляется, что этот фрагмент решает сквозную сложность рендеринга. |
| Методы учётных данных `config.rs` | Использует приватное файловое хранилище учётных данных, но считает нечитаемые или повреждённые файлы отсутствующими | Отклонено для Scriptor: сохранить OS keychain и отличать отсутствующее состояние от ошибок проверки. Не импортировать endpoints внешнего сервиса или контактные идентичности. |

Модульные тесты нативных Google-команд проходят (24), включая сохранение временных ошибок, обработку постоянных кодов, границы ответов, проверку токена и отклонение переполнения или нулевого времени жизни. Это локальная проверка; реальные учётные данные провайдера не использовались. Полное повторное чтение отчёта и оставшаяся работа по адаптации отслеживаются в [приложении к приёмке](../validation/REVIEW-REREAD-2026-10-01.md).
